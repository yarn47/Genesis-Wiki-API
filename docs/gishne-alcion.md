# 기쉬네 드리포드 · 알시온 블랙소드

## 근거와 재사용

- 기쉬네: 사용자 스크린샷 6549~6611. 필살기는 없음.
- 알시온: 사용자 스크린샷 6613~6659. 부동명왕검은 필살기이며 기본/발현 1·3·5단은 230/240/250/260%.
- 협공 연계 40/60/80/100%는 사용자 지정값. 다른 공용 아티팩트는 기존 항목을 연결한다.
- 출시일·등장 작품·장비 미착용 기본 스탯은 제공되지 않았으므로 입력하지 않았다.
- 알시온의 클래스 6개와 기쉬네의 기존 클래스 4개는 재사용한다.
- 워록의 세 액티브는 사용자 지시에 따라 위치와 동일한 스킬 ID를 공유한다. `skillsFrom`은 원본 클래스의 스킬 upsert가 끝난 뒤 관계만 연결하므로 새 스킬을 복제하지 않는다. 직접 스킬과 동시 지정하거나 참조를 연쇄하는 것은 허용하지 않는다.
- 다크메이지의 공용 부모는 위치로 유지한다. 캐릭터 상세 응답에서는 위치가 없고 워록이 있으면 워록을 부모로 표시한다. 다른 캐릭터의 트리에는 영향을 주지 않는다.

## 배포 순서 (아직 미실행)

1. 운영 DB 백업.
2. `db/migrations/010_kashmir_faction.sql` 적용. 기존 enum 값은 유지하면서 주/보조 진영에 kashmir를 허용한다.
3. kashmir enum 및 트리 연결 처리가 포함된 API 배포.
4. `scripts/gen_sql.py`로 검증·생성한 데이터를 기존 동기화 절차로 적용.
5. 신규 PNG와 카슈미르 필터가 포함된 프런트 배포.
6. 운영 화면에서 두 캐릭터, 공용 스킬 사용자, 효과 참조 및 신규 진영 필터 확인.

## 로컬 검증

- 데이터 테스트: `python3 -m unittest discover -s scripts/tests -p 'test_*.py'`
- SQL 생성·참조 검증: `python3 scripts/gen_sql.py >/dev/null`
- API 회귀 테스트: ClassTreeParentResolverTest, ActiveSkillServiceTest, CharacterRequestTest
- 프런트 빌드 및 읽기 전용 JSON 미리보기로 UI 확인. 실제 DB SQL 적용은 수행하지 않았다.
